<div class="markdown-heading" dir="auto"><h2 tabindex="-1" class="heading-element" dir="auto">Remove</h2><a id="user-content-remove" class="anchor" aria-label="Permalink: Remove" href="#remove"><svg data-component="Octicon" class="octicon octicon-link" viewBox="0 0 16 16" version="1.1" width="16" height="16" aria-hidden="true"><path d="m7.775 3.275 1.25-1.25a3.5 3.5 0 1 1 4.95 4.95l-2.5 2.5a3.5 3.5 0 0 1-4.95 0 .751.751 0 0 1 .018-1.042.751.751 0 0 1 1.042-.018 1.998 1.998 0 0 0 2.83 0l2.5-2.5a2.002 2.002 0 0 0-2.83-2.83l-1.25 1.25a.751.751 0 0 1-1.042-.018.751.751 0 0 1-.018-1.042Zm-4.69 9.64a1.998 1.998 0 0 0 2.83 0l1.25-1.25a.751.751 0 0 1 1.042.018.751.751 0 0 1 .018 1.042l-1.25 1.25a3.5 3.5 0 1 1-4.95-4.95l2.5-2.5a3.5 3.5 0 0 1 4.95 0 .751.751 0 0 1-.018 1.042.751.751 0 0 1-1.042.018 1.998 1.998 0 0 0-2.83 0l-2.5 2.5a1.998 1.998 0 0 0 0 2.83Z"></path></svg></a></div>
<p dir="auto">For example, to remove <code>*+~.()'"!:@</code> from the result slug, you can use <code>slugify('..', {remove: /[*+~.()'"!:@]/g})</code>.</p>
<ul dir="auto">
<li>If the value of <code>remove</code> is a regular expression, it should be a
<a href="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Regular_Expressions/Character_Classes" rel="nofollow">character class</a>
and only a character class. It should also use the
<a href="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/RegExp/global" rel="nofollow">global flag</a>.
(For example: <code>/[*+~.()'"!:@]/g</code>.) Otherwise, the <code>remove</code> option might not
work as expected.</li>
<li>If the value of <code>remove</code> is a string, it should be a single character.
Otherwise, the <code>remove</code> option might not work as expected.</li>
</ul>

<p dir="auto">The main <code>charmap.json</code> file contains all known characters and their transliteration. All new characters should be added there first. In case you stumble upon a character already set in <code>charmap.json</code>, but not transliterated correctly according to your language, then you have to add those characters in <code>locales.json</code> to override the already existing transliteration in <code>charmap.json</code>, but for your locale only.</p>
